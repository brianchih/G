1. 創新背景與概念動機

教學痛點：傳統講授式教學與複雜計算的距離

在《財務管理》等必修課程中，概念往往極為抽象且包含大量計算（如債券定價、存續期間、利率與債券價格敏感度關係）。學生若僅憑紙本 PPT 或靜態算式，難以建立直觀感受。

核心解決思維

  • 離線式 HTML 互動模組： 將原本散亂的 PPT 頁面提煉，利用 ChatGPT 快速生成可互動的單頁網頁（HTML/JS），直接上傳至 iClass 即可在無需連線或架站情況下開啟操作。
  • 視覺化動態感官體驗： 透過數值輸入、滑桿動態調整與動態曲線變化，讓學生直觀看見「當利率由 3% 變動至 20% 時，長短期債券價格變化的敏感度差異」。
  • 學習掌控權交還學生： 增加「動畫播放速度控制器（1x, 2x, 0.5x）」，配合現代學生習慣倍速觀看影音的習慣，提高自主學習意願。

2. 離線 HTML 互動教材製作流程

無須具備高深前端程式設計能力，透過給予 Prompt（提示詞）即可將簡報轉化為互動工具：

  1. 精簡素材與確立核心： 不盲目上傳整份投影片，僅抽取「最具爭議／最複雜」的核心頁面（如債券價格對利率敏感度）。
  2. ChatGPT 協助提煉結構： 丟入簡報內容，請 AI 建議「應保留哪些參數（如到期年數 1-30 年、市場要求報酬率、票面利率）」並定義視覺化變數。
  3. 迭代優化互動細節：
    • 更正座標軸意義（防止學生混淆 X/Y 軸意義）。
    • 新增學生自訂參數欄位與比對模式（Case 1 vs. Case 2）。
    • 加入變速播放控制（允許學生加速或慢速播放點位移動）。

3. AI 語音與對口人像工具整合與比較

為強化多感官學習，將重點整理結合 AI 語音與對口人像，減輕教師重覆錄製課後補充影片的負擔。

技術類型 / 工具 優勢 (Pros) 限制 (Cons) 適合應用場景
Web Speech API
ChatGPT 原生嵌入		 免額外費用、能隨學生輸入參數動態改變講稿內容與朗讀。 語音較為機械音、無法呈現對嘴嘴型。 課堂互動頁面實時動態導覽、數值變動解說。

免費文字轉語音		 免費、支援多國語言（台港口音、英/日/法/西語）。 需手動下載 MP3/MP4 後再封裝至 HTML 檔案中。 外籍生多語言旁白支援、課後重點摘要說明。

4. 生活化 HTML 應用與部署推廣

將 AI 生成 HTML 互動設計延伸至學生生活與創意情境，建立學生對 AI 工具應用的想像力：

專案 A：午餐吃什麼決策轉盤 (Food Spinner)

結合 Google 評論與餐廳分類，可手動新增口袋名單，運用手機開啟 HTML 進行隨機抽籤，解決校園日常痛點。

專案 B：動態天氣瓶與氣候模擬 (Weather Bottle)

串接線上氣象 API API 數據，隨著城市溫度變化動態繪製瓶內植物與雨雪狀態。

專案 C：情境藉口研究所 (Excuse Generator)

提供「量子力學風格、社畜文學風格、專業官腔風格」等多重情境藉口生成，增加互動趣味性。

部署技巧： 利用 Netlify 免費平台上傳 HTML 檔，生成公開網址並轉為 QR Code，即可在課堂中讓學生掃碼連線互動。

5. 教學實踐、師生互動與評量機制反思

教學現場觀察

  • 學生學習動機： 互動式工具與語音元件顯著提升了學生的專注度與探索意願（配合除錯加分機制效果更佳）。
  • 過度依賴 AI 報告的副作用： 開放 AI 後，學生簡報產出品質看似提升，但口頭報告時常「照本宣科」，無法回答深層延伸問題。

評量機制的轉變與回歸

評量設計策略： 平時學習全面開放並鼓勵使用 AI 工具；期中／期末考則回歸傳統「閉卷筆試」或「評析 AI 錯誤答案」。
  • 平時： 給予無標準解答題目，鼓勵學生透過 ChatGPT 與 HTML 工具摸索。
  • 評量： 出題「AI 產出的錯誤解答」，請學生找出其邏輯瑕疵或錯誤假設（測驗真正的理解深度）。
  • 教學實踐研究計畫： 利用計畫經費核銷 AI 訂閱費用（ChatGPT Plus, 語音工具），並以期中考前後學習成效做對照組與實驗組分析。

6. 專家改良建議與教學升級行動計畫

針對本次示範內容，建議從以下 5 大維度進行升級優化：

  1. 建構專屬教學 Prompt 範本庫： 建立標準化的 Prompt 語法範本（如指定 HTML5 + Tailwind CSS + Chart.js），讓生成的互動元件視覺更專業、程式碼更穩健。
  2. 強化引導式問答（Scaffolding）： 在 HTML 工具中加入「學習單檢核機制」（例如：當學生把利率調到 15% 時，網頁跳出思考題「此時債券價格呈現何種變化？請勾選」），避免學生只當成遊戲滑過。
  3. 簡化語音/影片整合工作流： 優先採用 Web Speech API（直接用 JS 發音）或預先匯入開放 TTS API，減少手動下載/剪輯 MP4 的耗時過程。
  4. 將 AI 除錯納入正式評量項目： 如同行名師建議，將「抓出 AI 算錯／語意瑕疵」設為學習單主要題型，將學生從「AI 內容接收者」提升為「AI 內容審查者」。
  5. 規劃完整教學實踐研究計畫數據收集： 建議在互動 HTML 頁面中加入埋點（如計數器記錄學生操作次數/停留時間），作為實證教學研究計畫（MOE Teaching Practice Research Program）的數據量化指標。
